# 产品方案：从 Morse 切入的编码工具站

版本：2026-10-13，视觉A已确认，本次执行批0+批1双语MVP。执行顺序见 [开发计划](development-plan.md)。用户最新要求：**移动端优先，接近原生 app 体验**。用户已购买 `dotsdashes.com` 并确认Cloudflare部署；品牌文字先按DotsDashes，目标国家和商业化方式尚未确认；英文优先，同时支持简体中文，面向国际访客设计，美国英文查询作为研究偏好而非已确定市场。

## 产品定位与成功标准

让用户在手机上迅速把文本、符号、声音互相转换，并能理解、校验和带走结果。初期服务三类任务：收到一段代码要读懂；生成一段信号要复制/播放/下载；学习或制作教学材料。后续拓展开发者编码与解谜工具。画像详见 [逐工具目录](tool-catalog.md)，它们是研究假设，不是已完成的用户访谈。

初期不要求注册，不依赖远程 AI 或转换 API。主流程为进入页面→输入或选示例→立即查看结果→复制/试听/下载。完成结果比页面停留时长重要，不用长篇导语、弹窗或广告打断这一流程。

搜索排名只能证明页面在本次查询中出现，不能证明功能使用量或转化率。关键词月量/CPC/KD 均沿用用户提供的未验证输入，不据此估算广告收入或给出外链配额。原始数据见 [SEO 输入表](../docs/research/seo-input.md)，政策复核见 [SEO review](../docs/research/seo-review.md)。

## 路由与阶段决策

具体批次以 [内页开发优先级](development-plan.md) 为准：批0首页；批1 Alphabet/Generator；批2 Numbers/SOS/Chart；批3 Practice/Tattoo；批4 Binary/Base64/Hex/NATO；批5选择性扩展简单密码及URL工具。音频Decoder、无key Vigenère、Semaphore和Braille先验证再排期。

独立页面必须提供独立任务价值：Generator交付可用音频文件；Chart交付打印材料；Practice提供练习反馈；Tattoo提供可校验图形/手链布局；复杂解码需要实际样本与诊断能力。

`/text-to-morse-code`、`/morse-to-english` 初期作为首页的两种模式与正文覆盖词；`/morse-code-audio` 先作为 generator 的功能/意图；bracelet 作为 tattoo 页的一种设计模式。未存在的 URL 不创建重定向或空壳，只在真实链接/迁移需要时实现。若后来拆页，必须给出新任务与实质功能，使用 GSC 查询和任务行为检验。

Alphabet 与 chart 的区别是“学习/试听”与“下载/打印”；generator 与首页的区别是“制作可用文件”与“快速翻译”。它们共享底层算法，不共享整页模板和同一段冗长介绍。SERP 依据见 [样本](../docs/research/serp-sample.md)。

## 信息架构与导航

长期工具族：Morse / Text & Data / Ciphers / Signals。首发仅显示已上线的 Morse 工具。首页本身就是翻译器，不先放一个工具目录落地页。页面下方按“你接下来要做什么”链接到查表、练习、音频制作等。

移动端：紧凑顶栏（品牌、工具菜单）；任务模式位于表单上方；结果和下一步操作紧跟输入。常用动作 44–48px 触控目标；高级参数放原生 details 或可访问的底部面板。键盘打开时收起非必要固定栏，允许滚动，不遮输入、不自动滚动抢焦点。返回保留当前内存状态，跨工具带入文本必须由用户触发。

无需一开始做 PWA 安装引导。基础站完成后评估 manifest、图标、离线核心功能和可更新缓存；安装入口只在支持且有重复使用意愿时出现。移动网页不能保证所有原生能力，尤其 iOS 后台音频、振动和文件保存，需要实机验收。

## 首屏规格：Morse Code Translator

1. H1 `Morse Code Translator`，一句说明 `Translate text, hear the signal.`，不占用大幅 hero。
2. 明确 Text → Morse / Morse → Text；示例可填 HELLO、SOS、2026。默认保留空输入或清楚标注示例。
3. 输入区 label、清空、字符数；Morse 模式提供点/划/字母间隔/单词间隔的触控辅助输入。
4. 结果区可选中复制；未知符号用占位并附位置，不把部分结果当完整成功。
5. 主要动作 Copy / Play / Stop；音频参数默认折叠，常用速度可直接调整。
6. 下方提供当前结果的逐字解释，再给 A–Z/0–9 速查与有用问答；不是每个页面都强加整表。

状态：空值（禁用依赖结果的动作）、有效结果、部分错误、全部错误、复制成功/失败、播放/停止、文件生成中/取消、超长输入。模式切换需要确定输入是否可以无损转移；非法输入存在时保留原文，不自动覆盖。

## 功能优先级与验收

P0：正确映射、标准间隔、可理解的错误、双向转换、复制、Web Audio 播放/停止、手机可用。P1：WAV下载、逐字高亮、Farnsworth、数字/SOS专题。P2：练习、打印、纹身/手链图稿。候选新需求及来源见 [竞品分析](../docs/research/competitors.md)。

首发验收：375/390/430px 和桌面；iOS Safari 与 Android Chrome；英文键盘/粘贴/选中；锁屏后恢复不会继续意外发声；非法字符、重复点击播放、切页和清空均停止旧音频；下载文件可在本机重新播放。离线能力只有实测后才能宣传。

## 需求验证与运营

首批邀请 5–8 位用户完成“解谜”“分享给朋友”“课堂演示”任务，观察是否找得到输入/复制/速度，是否理解错误。后续分别找教师/无线电爱好者/开发者验证专业功能。人数是内部计划，不是统计显著性。

匿名事件仅含工具、方向、动作、错误类型、耗时档位；不采集输入、输出、录音、文件名或敏感 URL。指标：首次有效结果、结果复制/播放/下载成功率、错误后的修复率、7日重复使用；事件不是文本正确性的证明，算法需标准测试。

每周检查抓取/索引与关键错误，每 2–4 周评估查询覆盖及功能投入。后续广告只考虑工具下方或不会造成布局跳动的区域；不在首屏插屏，不以预估 CPC 直接决定扩展。视觉采用用户确认的A方案；域名采用dotsdashes.com，平台采用Cloudflare；初期市场与变现路径待确定，但不阻塞批0开发。发布前完成对应配置，本轮包含GitHub提交、main生产自动部署和其他分支共享dev自动部署；GSC提交不在本轮授权任务范围。
