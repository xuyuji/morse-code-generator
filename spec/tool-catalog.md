# 工具目录、用户画像与场景

研究日期：2026-10-13。状态：产品规划稿，尚未实现。覆盖 SEO 清单的 25 个页面意图；手链并入纹身设计工具。

本文中的画像、场景、优先级、成功标准均为**产品假设**，不是用户访谈或已验证的市场结论。标准事实以文末一手资料为依据；搜索量/KD不作为这些画像的证据。上线后用工具完成率、错误率、复制/下载事件与简短用户反馈验证，统计事件不得携带用户原文。

## 共用决策

- 分为转换器、参考表、练习器、创作器四种产品形态。参考页不强塞双向转换；训练页不让长表格抢占练习入口。
- 所有字符处理规则可见；未知字符不静默丢弃；解码失败定位到片段，保留输入。
- 文本、编码、声音默认在客户端处理。数据表和算法随版本发布，不需要付费 API 或实时数据库。大资源按需加载。
- 分享默认分享工具及设置，不自动把私人文本写进 URL；明确选择后才生成带内容的分享链接。复制、下载提供状态反馈。
- 下文阶段为建议：**A 核心上线**、**B Morse 深化**、**C 相邻编码扩展**、**D 独立验证后扩展**。这不是按月搜索量机械排序，也不代表同时公开全部路由。
- 首页、generator、text-to-morse、morse-to-english 共享同一套转换内核。独立 URL 只有在首要任务和交付物明显不同后才上线；不先创建占位页。

## 移动端优先与接近原生 App 的交互约束

这是用户已明确的产品要求，不是待验证假设。所有工具先设计窄屏主任务，再扩展桌面布局。

- **单手完成：**主要按钮至少 44×44 CSS px；播放/停止、复制、下载等当前任务的主动作位于容易触达处。同屏只突出一个下一步，复杂选项用可关闭底部面板；不把全部参数堆在工具之前。
- **软键盘：**编辑时保留可见结果摘要，不强制跳动或自动滚页；固定底栏适应可视视口与安全区，不覆盖键盘上方输入/错误提示。切换模式保留原输入，清空可撤销。
- **布局：**手机采用输入 → 结果 → 动作的单列流程，桌面可并排；Morse 手动点划按钮直接触摸即可，不能依赖鼠标 hover；参考表可筛选而不是让用户横向滚一张大表。
- **低网速：**核心字符表和转换内核与页面一起可用；音频、练习、大型盲文库按需加载且有加载/失败状态；不让外部字体或第三方脚本阻塞输入。离线/PWA 安装属于后续增强，不能提前声称已支持。
- **反馈与无障碍：**复制用短状态提示；播放始终有停止入口，失去焦点/系统中断后状态一致；错误不只靠颜色；读屏能读出点划、点位和旗位含义。减少动态效果时不强播闪烁。
- **工具差异：**练习页默认手机键盘快速作答；数字页使用适当数字输入提示但保留前导零；hex/binary/base64 文本不可被自动大写/纠错；创作器预览先适应屏幕，再提供缩放；chart 手机上提供下载/分享文件入口，打印设置收起。
- **验证：**至少覆盖 360 px 窄屏、iOS Safari 与 Android Chrome 的软键盘展开、横竖屏、慢网加载、复制权限失败、音频中断和文件下载/分享降级。浏览器原生能力存在差异，失败时必须有可用替代动作。

## 01 首页 `/` — Morse Code Translator

**画像假设：**第一次接触 Morse 的普通用户、解谜者；没有术语知识，只想“看懂/写出这串点划”。

**典型场景：**①从游戏复制 `... --- ...`，立刻得到 SOS 并听声音；②将一段英文转成点划，复制到聊天或作业。

**输入 → 输出：**英文、数字、支持的标点 ⇄ International Morse；文本结果、字符对应高亮、可选试听。

**核心需求：**移动端首屏输入和结果摘要连续可见、宽屏才用双面板、明确方向切换、实时结果、示例、复制、清空、播放/停止；空状态教会“字母空格、单词斜杠”的默认约定。成功是无需读教程完成一次转换。

**边界：**不等于语言翻译；不支持字符逐项提示；无分隔点划具有歧义，不伪造唯一答案；国际 Morse 与其他体系不能混用。播放须用户触发。

**依赖与阶段：**ITU 字符/时序表 [S1]、浏览器声音合成 [S2]；无运行时外部数据；A。

## 02 `/morse-code-generator` — Morse Code Generator

**画像假设：**视频/播客创作者、课堂素材制作者；关心可带走的声音和格式。

**典型场景：**①给短视频制作一个名字的 Morse 音效；②教师生成指定速度的听写音频。

**输入 → 输出：**文本 + 速度/音高/间隔 → Morse、预估时长、试听、WAV 下载。

**核心需求：**下载与播放同样突出；设置折叠；声音与显示采用同一个事件序列，导出结果与试听一致。

**边界：**长文本先显示时长/体积限制；字符速度和有效速度不能混淆；更改设置后旧文件需重新生成；不承诺所有浏览器直接导出 MP3。

**依赖与阶段：**[S1][S2]，本地 WAV 编码，无外部音频素材；B，只有可靠导出做好才独立上线，否则入口落在首页功能区。

## 03 `/morse-code-alphabet` — Morse Code Alphabet

**画像假设：**学生、家长、初学者；需要查一个字母并建立声音记忆。

**典型场景：**①查名字中每个字母的点划；②点选容易混淆的 S/H，比较节奏。

**输入 → 输出：**字母搜索/点选 → A–Z 速查卡、声音、示例；数字作为相关入口。

**核心需求：**可筛选、可键盘操作、字母/点划大而清晰、点一个听一个。成功是快速找到目标字符。

**边界：**视觉记忆图不能冒充唯一标准；不自动播放整表；标明支持字符范围。

**依赖与阶段：**[S1][S2]；A，参考页，无须完整双向编辑器。

## 04 `/morse-code-decoder` — Morse Code Decoder

**画像假设：**解谜者、短波听众；有一段未知信号，需要解读和纠错。

**典型场景：**①粘贴混有不同破折号的 Morse，修正分隔后解码；②上传录音或手动敲击，把信号转成候选文本。

**输入 → 输出：**首期点划/手动输入 → 文本与错误位置；后续音频 → 检测片段、候选字符与可调参数。

**核心需求：**点/划/字母间隔按键、局部纠错、解释无法识别原因；音频模式应让用户确认速度与噪声处理。

**边界：**音频解码是独立信号处理项目，不是生成音频的反向按钮；录音噪声、速度变化、多个音源可能失败；不宣称“任意录音准确识别”。

**依赖与阶段：**文本路径 [S1] 无外部数据；音频使用本地 DSP/Web Audio [S2]，需要自建有许可测试录音；B。未做独特输入与纠错前并入首页解码模式。

## 05 `/morse-code-numbers` — Morse Code Numbers

**画像假设：**学习者、礼物设计用户；想表达日期、年份或编号。

**典型场景：**①把纪念日转换成点划做手链；②比较 1–5 与 6–0 的规律做练习。

**输入 → 输出：**数字字符串/日期文本 → 数字 Morse、0–9 对照、逐位试听。

**核心需求：**保留前导零；日期格式由用户决定；示例可编辑；数字分组可视化。

**边界：**不要把 `007` 当数值 7；不要替用户把 03/04 解释成特定日期；小数点/斜杠仅在已支持标点表时转换。

**依赖与阶段：**[S1]；无外部数据；B。

## 06 `/sos-morse-code` — SOS Morse Code

**画像假设：**学生、户外知识学习者；要确认 SOS 的节奏和写法。

**典型场景：**①课堂演示三短三长三短；②离线前打印一张节奏说明卡。

**输入 → 输出：**播放/速度操作 → SOS 连续信号、节拍可视化、简明用法。

**核心需求：**直接听到正确节奏；区分视觉分组 `... --- ...` 与连续求救信号的发送时序；支持停止和重复次数。

**边界：**网站不发送救援请求，不冒充应急通信设备；不依赖手机闪光灯能力；禁止自动持续闪烁，视觉信号需显式触发并尊重减少动态效果偏好。

**依赖与阶段：**[S1][S2]；无外部数据；B，参考/演示页。

## 07 `/morse-code-chart` — Morse Code Chart

**画像假设：**教师、童军活动组织者、初学者；要打印或随手保存的完整表。

**典型场景：**①打印 A4 黑白表贴在教室；②下载手机清晰可读的速查图。

**输入 → 输出：**纸张/范围/深浅样式 → 字母数字标点图表、打印版/PDF。

**核心需求：**A4 与 Letter、不截断、可选标点、来源/版本、小字号仍清晰；HTML 表格也能访问。

**边界：**不要直接下载/复用竞品图；不是 alphabet 页换标题，交付重点必须是打印和下载。

**依赖与阶段：**[S1] 数据，本项目自行排版矢量素材，无外部 API；B，导出产物验证后上线。

## 08 `/morse-to-english` — Morse to English

**画像假设：**非技术用户、解谜新手；把“译成英文”理解为解码。

**典型场景：**①收到点划消息想知道内容；②作业答案只有 Morse，需逐字核对。

**输入 → 输出：**点划 → 拉丁字母/数字文本与字符对应。

**核心需求：**解码默认打开、可见分隔例子、错误定位。

**边界：**解码不会把外语句子翻译成英语；无间隔信号不可靠；需求与首页高度重叠。

**依赖与阶段：**[S1]；A 提供功能，独立路由暂缓；未来只有独特的解码教学和任务证据才拆页。

## 09 `/morse-code-practice` — Morse Code Practice

**画像假设：**有持续学习目标的初学者、业余无线电入门者；希望听到后认出字符。

**典型场景：**①每天 5 分钟练习两三个易混字符；②按已学字符集做一轮听写并复习错题。

**输入 → 输出：**练习范围/速度/答案 → 即时反馈、正确率、易错字符、本地进度。

**核心需求：**开始即练、可重听、键盘作答、结束总结；先做字符识别，再扩词组；Koch/Farnsworth 若提供，必须明确训练规则与速度含义。

**边界：**不能把随机播放称为完整课程；成绩按练习设置解释；音频关闭时提供可操作替代；清除本地记录可见。

**依赖与阶段：**[S1][S2]；自编/许可清晰词库，本地存储；B，训练法细节上线前补专项资料验证。

## 10 `/text-to-morse-code` — Text to Morse Code

**画像假设：**普通用户、社交内容创作者；只需把一句话变成点划。

**典型场景：**①把 “I love you” 转成消息；②把自己的名字转成 Morse 放简介。

**输入 → 输出：**文本 → Morse、复制、试听。

**核心需求：**输入即转、明确不支持的字符；不需要专业设置常驻。

**边界：**不自动罗马化中文或移除重音；保留输入并提示可用替代。

**依赖与阶段：**[S1]；A 首页编码模式承接，独立路由暂缓；不要仅靠 SEO 词序拆页。

## 11 `/morse-code-audio` — Morse Code Audio

**画像假设：**听觉学习者、音效使用者；主要目的为听/下载声音。

**典型场景：**①慢速听自己的名字；②设置音高、循环间隔制作听力练习素材。

**输入 → 输出：**文本/Morse + 声音设置 → 播放器、节奏高亮、音频文件。

**核心需求：**播放/停止、进度、音量、WPM、频率、时长，设置改变后结果一致。

**边界：**浏览器可能要求点击后才能启用声音；挂起/切后台要正确停止；不强依赖第三方文件或语音 API。

**依赖与阶段：**[S1][S2]；B 功能实现；与 generator 高度重叠，优先一个音频工作台，独立页待意图区分证据。

## 12 `/morse-code-tattoo`（含 Bracelet）— Morse Design

**画像假设：**纪念纹身/手链买家、手工制作者；最怕拼错、间隔错和设计不可制作。

**典型场景：**①输入名字查看横向/纵向纹身预览；②把纪念短语转成圆珠/长珠手链，估算珠数与长度。

**输入 → 输出：**短文本 + 排版/点划尺寸 → 字符核对、SVG/PNG 预览；手链模式输出珠子清单与估算长度。

**核心需求：**原文始终可见、反向核对、清楚字母/词间隔、打印给制作者。先功能样图，后评估款式模板。

**边界：**预览不是纹身效果或工艺保证；镜像必须显式标注；手链长度需输入珠尺寸/间隔/收尾余量；不把竞品首饰照片用作素材。

**依赖与阶段：**[S1]；自主 SVG 图形，无电商/库存 API；B 后段，有用户导出需求后上线。

## 13 `/binary-translator` — Binary Translator

**画像假设：**学生、程序员、解谜者；既有“文本变二进制”也有“数字进制转换”需求。

**典型场景：**①验证 A 对应字节 `01000001`；②把 UTF-8 文本转字节，排查非 ASCII 内容。

**输入 → 输出：**文本 ⇄ 按字节分组的二进制；整数转换作为明确独立模式。

**核心需求：**默认 UTF-8、字节数、8 位分组、可复制；解释字符与字节不总是一对一。

**边界：**非法位、非 8 倍长度、无效 UTF-8 均提示；不将 UTF-16 code unit 当通用字符编码；整数模式避免浮点精度丢失。

**依赖与阶段：**浏览器 TextEncoder/TextDecoder 与 Encoding Standard [S3]，无外部数据；C。

## 14 `/base64-decode` — Base64 Decode

**画像假设：**开发者、支持工程师；要检查接口/配置中的编码内容。

**典型场景：**①解码 API 返回字段并保留中文；②识别 Base64URL 字符串或下载解码后的二进制文件。

**输入 → 输出：**Base64/Base64URL ⇄ UTF-8 文本/字节；明确文本与文件模式。

**核心需求：**默认解码、变体显式选择、错误位置、字节/文本视图、复制和下载。

**边界：**Base64 是编码不是加密；严格校验字符与 padding，宽松兼容需显式开关；不把二进制硬当文本；不渲染解码出的 HTML；大文件限制需可见。

**依赖与阶段：**RFC 4648（含测试向量）[S4]、[S3]，无外部数据；C。输入内容不能进入分析日志。

## 15 `/nato-phonetic-alphabet` — NATO Phonetic Alphabet

**画像假设：**客服、跨语言通话者、无线电入门者；在嘈杂通话里准确报字母。

**典型场景：**①将订单号转换后逐个报给客服；②学习名字的标准拼读词。

**输入 → 输出：**字母/混合编号 → 拼读词序列和 A–Z 对照表。

**核心需求：**原字符与拼读词同排、通话时大字显示、数字保留策略明确、可复制。

**边界：**采用官方 Alfa/Juliett 拼法；不要把地方习惯当 NATO 标准；浏览器 TTS 不代表标准无线电发音，若加真人音频需许可。

**依赖与阶段：**NATO 官方表 [S5]；本地固定映射；C。

## 16 `/hex-to-decimal` — Hex to Decimal

**画像假设：**程序员、电子/计算机学生；需要快速而精确转换数值。

**典型场景：**①把 `0xFF` 转成 255；②把长十六进制 ID 转十进制并核对位数。

**输入 → 输出：**十六进制整数 ⇄ 十进制整数；可展开逐位计算。

**核心需求：**接受可选 0x 前缀、大小写、整数字符串精确计算、复制；简易解释可折叠。

**边界：**默认数学整数，不默认二补码；负数/位宽/有符号需单独定义；不使用 Number 承接任意大整数；小数不在首版范围。

**依赖与阶段：**纯本地 BigInt 算法，无外部数据；C，数据规则为项目决策，测试覆盖超出安全整数范围。

## 17 `/braille-translator` — Braille Translator

**画像假设：**教育工作者、设计师、盲文初学者；真正盲文读者也可能使用，准确性和无障碍要求高。

**典型场景：**①学生对照一个英文单词的点位；②设计师检查文字转写并交专业人员复核。

**输入 → 输出：**明确语言/规则/收缩等级后的文本 ⇄ 盲文结果；Unicode 点位显示与真正转写分开命名。

**核心需求：**展示大小写/数字等指示符、点位文字说明、键盘与读屏可用；正式转写采用可追溯表和版本。

**边界：**逐字母 Unicode 替换不等于 UEB 转写；不能承诺适合直接压印、无障碍标牌或专业出版；视觉点字符不保证触觉尺寸；反向转换可能有歧义。

**依赖与阶段：**UEB 规则 [S6]、Liblouis 及语言表 [S7]，可能需 WASM/较大静态包；运行时可不联网，但需审查许可证和表版本，并请熟悉盲文者验证；D 独立立项，不作为低成本扩页。

## 18 `/url-decoder` — URL Decoder

**画像假设：**开发者、运营排障人员；要读懂 query 参数、回调 URL。

**典型场景：**①解读 `%E4%BD%A0` 等 UTF-8 内容；②排查表单参数里 `+` 是空格还是字面加号。

**输入 → 输出：**percent-encoded 字符串 ⇄ 解码文本；明确“组件”和“表单参数”模式。

**核心需求：**默认只解码一层、显示转换差异；重复解码手动触发；保留错误输入。

**边界：**`+` 只在对应表单规则中当空格；无效 `%`/字节序列不静默修复；不要自动打开解码后的 URL；整 URL 结构与组件不能混为一谈。

**依赖与阶段：**WHATWG URL Standard [S8]、[S3]，无外部数据；C/D，先确认定位与需求，不因 CPC 上线。

## 19 `/caesar-cipher-decoder` — Caesar Cipher Decoder

**画像假设：**学生、逃脱游戏/谜题玩家；可能知道或不知道位移量。

**典型场景：**①输入密文和 shift=3 验证作业；②列出所有位移候选，人工找到可读答案。

**输入 → 输出：**文本 + 位移/穷举选项 ⇄ 编解码结果、位移表。

**核心需求：**A–Z 对照、保留标点规则、所有候选可复制、解释单字母映射。

**边界：**候选排序不等于保证解密正确；默认英语 26 字母；不声称可保护秘密。

**依赖与阶段：**本地映射；CrypTool 一手实现参考 [S9]；若加英语评分需可授权频率表；D。

## 20 `/vigenere-cipher-decoder` — Vigenère Cipher Decoder

**画像假设：**密码学学习者、谜题玩家；有密钥时要可靠解码，无密钥时想获得线索。

**典型场景：**①输入 `LXFOPVEFRNHR` 和 `LEMON` 核对结果；②对较长密文分析可能密钥长度。

**输入 → 输出：**文本 + key → 编解码结果、密钥重复对齐；破解模式另行立项。

**核心需求：**标明重复密钥 Vigenère 变体；字符映射与密钥对齐可见；空白是否推进密钥有固定规则。

**边界：**空密钥报错；Autokey/Beaufort 不能混称同一算法；无密钥、短文本不保证恢复原文。

**依赖与阶段：**基础算法无需数据；参考 CrypTool [S10]；未来自动破解需语言频率/词典与评测集；D，先做有密钥转换。

## 21 `/tap-code` — Tap Code

**画像假设：**历史/童军学习者、谜题玩家；想通过敲击传短消息。

**典型场景：**①把单词转成两组敲击；②收到行列数字后用 5×5 表查字母。

**输入 → 输出：**文本 ⇄ 行列数/敲击序列，表格高亮和声音演示。

**核心需求：**展示所选字母表、明确先行后列、字符与词间隔；敲击按键可操作。

**边界：**采用明确标记的 C/K 合并变体时，反向结果不能恢复原字母；不要与 Morse 音节相混；录音识别首版不做。

**依赖与阶段：**NSA 的 Tap Code 教育材料为需求与规则核验入口 [S11]；本地表与声音，C/K 具体字母表上线前需逐格复核原始图；D。

## 22 `/leetspeak-translator` — Leetspeak Translator

**画像假设：**游戏/社交用户；要生成昵称、看懂变形文本。

**典型场景：**①把昵称转换成容易读的 leet；②比较轻度和重度替换后选择喜欢的版本。

**输入 → 输出：**文本 → 多档 leet 候选；反向提供可能文本。

**核心需求：**风格强度、保留可读性、复制、可重复的结果；解释常见替换。

**边界：**不存在本项目已核实的统一权威标准，须标为本站映射；同符号多义，反向不可保证唯一；不要宣称密码强度提升。

**依赖与阶段：**自有、版本化映射表，不需要外部 API；D，待实际差异化需求再做。

## 23 `/bacon-cipher` — Bacon Cipher

**画像假设：**古典密码学习者、解谜/出题者；识别两种符号构成的隐藏信息。

**典型场景：**①将 A/B 五位组解成字母；②把一句话编码为二元序列用于课堂谜题。

**输入 → 输出：**文本 ⇄ 五位 A/B 组；可选二元符号。

**核心需求：**明确 24/26 字母变体、显示表、逐组校验；默认先做纯 A/B，不先做复杂排版隐写。

**边界：**I/J、U/V 合并规则因变体不同；不足五位、非法组需标注；字体样式隐藏可能在复制后丢失。

**依赖与阶段：**本地表；CrypTool 教育工具目录确认其教学用例 [S12]，24/26 表的逐项权威校验尚待实现前补充；D。

## 24 `/a1z26-cipher` — A1Z26 Cipher

**画像假设：**低门槛解谜者、老师/家长；希望数字与字母直观对应。

**典型场景：**①把 `8-5-12-12-15` 解成 HELLO；②制作孩子姓名的数字谜题。

**输入 → 输出：**A–Z ⇄ 1–26 数字组；表格和过程。

**核心需求：**默认 A=1、分隔符明确、词间隔可见、复制。

**边界：**无分隔 `111` 有歧义；0、27 等提示非法；A=0 属于另一个显式模式，不自动猜；非英文字符不丢弃。

**依赖与阶段：**本站明确公布的映射约定，无需外部数据；D。尚未以“国际标准”名义引用来源。

## 25 `/semaphore-flags` — Semaphore Flags

**画像假设：**童军教师、视觉学习者、解谜玩家；要理解双臂旗位并练习发送。

**典型场景：**①输入一个名字逐字展示动作；②教师打印参考表让两组学生互传消息。

**输入 → 输出：**字母 → 旗位序列/步进动画；点选两个旗位 → 候选字符。

**核心需求：**明确发送者/接收者视角，前后步进、速度、文本替代描述；“Attention/Ready”等控制信号与字母区分。

**边界：**镜像会改变理解，视角始终标注；双旗姿势不是国际单面信号旗字符表；不承诺摄像头姿态识别。

**依赖与阶段：**Scouts 实践材料和信号图 [S13] 用于规则核验；原创 SVG 人物/旗帜，不能直接重用有版权图；D，逐字姿态复核后发布。

## 研究来源与证据边界

以下为 2026-10-13 查询到的一手规范或项目自有材料。它们支撑技术边界，不证明市场大小、用户比例或 Google 排名。标准/算法和我们的功能设计分开维护；落实时把采用的版本、字符表、测试向量与许可证写入实现说明。

- **[S1] ITU-R M.1677-1 (2009), International Morse code**：[推荐标准页面](https://www.itu.int/rec/R-REC-M.1677-1-200910-I/)、[原始 PDF](https://www.itu.int/dms_pubrec/itu-r/rec/m/R-REC-M.1677-1-200910-I%21%21PDF-E.pdf)。用于 Morse 字符与信号时序；不是现代 UI 设计规范。
- **[S2] W3C Web Audio API**：[规范](https://www.w3.org/TR/webaudio-1.0/)。支持本地声音合成的技术基础；WAV 导出、交互和音频解码准确率仍需自己实现/验证。
- **[S3] WHATWG Encoding Standard**：[规范](https://encoding.spec.whatwg.org/)。支撑字节、UTF-8、编码/解码 API；本产品选择默认 UTF-8，不假定一个 Unicode 字符等于一个字节。
- **[S4] IETF RFC 4648**：[规范与测试向量](https://www.rfc-editor.org/rfc/rfc4648)。定义 Base64、Base64URL、padding 与非字母表字符的处理要求；本项目宽松兼容需显式区别于严格模式。
- **[S5] NATO**：[The NATO Phonetic Alphabet](https://www.nato.int/en/about-us/nato-history/history-by-theme/symbols-of-nato/nato-phonetic-alphabet)。标准拼读表的一手来源。
- **[S6] ICEB**：[Unified English Braille](https://iceb.org/publications/ueb/)。当前页面列出 2024 年第三版 UEB 规则及技术材料更新；盲文不仅是可见字形替换。
- **[S7] Liblouis**：[项目文档](https://liblouis.io/documentation/liblouis.html)、[表元数据](https://liblouis.io/documentation/liblouis/Table-Metadata.html)、[官方文档源码](https://github.com/liblouis/liblouis/blob/master/doc/liblouis.texi)。翻译语言/表是显式输入，需要选择、版本和许可管理；尚未选择具体浏览器发行包。
- **[S8] WHATWG URL Standard**：[规范](https://url.spec.whatwg.org/)。区分 percent encoding 与表单序列化/解析中的 `+` 语义。
- **[S9] CrypTool**：[功能目录](https://www.cryptool.org/en/functions/)。一手展示 Caesar/ROT13 与分析功能，用作功能边界参考，不视为互联网标准。
- **[S10] CrypTool**：[Vigenère 工具与算法说明](https://legacy.cryptool.org/en/cto/vigenere)。一手说明密钥重复、字符表与处理选项；本项目不照搬其历史人物归因。
- **[S11] NSA**：[No Such Puzzle: Tap Codes](https://www.nsa.gov/Puzzles/View/Article/3860720/no-such-puzzle-tap-codes/)。一手教学用例，具体字母表须进一步查看其图示后固化。
- **[S12] CrypTool**：[Online 工具目录](https://www.cryptool.org/de/cto/?Itemid=102)。包含 Bacon 教学工具；不是本次所有 Bacon 变体映射均已验证的证明。
- **[S13] The Scout Association**：[Semaphore 活动](https://www.scouts.org.uk/activities/practice-semaphore-signalling/)、[信号表 PDF](https://prod-cms.scouts.org.uk/media/5508/generic-resources-semaphore-signals.pdf)。支持教学和发送/接收流程参考；插图有版权，应自行重绘并核对。活动页历史性叙述不作为密码学算法标准引用。
